# 分享记录与限流

个人用量、成就、周报、账单及群分析在打开微信转发前准备公开摘要，以便一次点击转发。生成记录不表示用户已经发送；五分钟缓存与相同内容指纹复用用于减少重复准备。用量更新、周期或样式改变时可能产生不同摘要，因此不能用每天生成的记录总数当作实际转发次数。

服务端取消原有的“过去 24 小时最多 50 条新记录”限制，改为每账号滚动一分钟最多准备 60 条不同的新摘要。相同内容存在有效记录时直接返回，不占新增名额；各账号互不影响。限流条件与插入／恢复撤销或过期记录处于同一条 SQL 内，避免并发请求突破上限；超过时返回 429、`Retry-After: 60` 和“分享准备较频繁，请稍后再试”。一分钟窗口结束后可重试，不必等到次日。

原有分享的内容、有效期、撤销、来源失效与账号注销规则保持有效；不删除记录、不重置计数、不改用量。继续使用 `usage_shares` 及 `(user_id, created_at)` 索引，无需数据库迁移、更新电脑采集器或重新上传数据。只需部署服务端，小程序原有的刷新重试即可使用新规则。

测试覆盖已有 50 条历史记录仍可继续准备、相同内容复用、短时上限、并发写入、账号隔离、窗口恢复以及撤销／过期记录。测试仅使用内存数据库；生产排查只读账号自己的记录数量，不公开分享 ID 或摘要内容。
