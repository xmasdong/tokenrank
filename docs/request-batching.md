# 页面请求合并与缓存复用

普通统计继续使用 5 分钟内存缓存。首次查看某个周期、缓存到期和下拉刷新取新数据；短时间返回页面、切回已看周期、切图表或工具／模型时直接展示已读取结果。缓存不写入手机持久化存储，反复点击不会延长原有过期时间。

## 合并入口

- `GET /api/my/groups-overview?period=…`：当前用户资料、同步状态和群排名列表。所有群的名次、参与人数、更新时间用固定数量的 SQL 聚合，先按人数和最近更新排序，再取前 50 群。
- `GET /api/my/overview?period=…`：当前用户资料及个人用量，复用本次会话身份；历史总量和活跃记录共享一次日桶读取。用量不可用时可以单独返回 `usage_error`，不丢掉已取得的资料。
- `GET /api/groups/:id/page?period=…`：当前用户、群资料、榜单第一页和群分析共用入口，重复的身份、成员、人数查询只做一次。未加入或尚待完善资料时不附带榜单／分析。榜单仍按每页 50 人续页；本人在第 50 名之后也保留自己的名次。
- `GET /api/my/analysis?bundle=1`、`GET /api/insights?bundle=1`：工具和模型共用一组 D1 事务读取，返回 `tools`、`models`。在 SQL 端聚合，不把全部历史原始行读进 Worker。工具内部模型的联合分布仍使用独立的明细查询，不从独立比例猜测。
- `POST /api/shares`：直接返回可绘制的作者快照，分享页不再预先 GET 一遍个人用量。`include_ranking=true` 且 `style=usage` 时，同响应带最多前五名的 `ranking`，与作者数字／名次一致才允许生成。该渲染数据不存进公开分享，匿名读取仍只有原有白名单。没有历史返回 `NO_USAGE`，不创建公开记录。

旧读取接口继续保留，老版本小程序可以使用。新合并入口会将各部分按原始缓存键回填，后续进入个人、群分析等页面可继续复用。已有用户资料时，仅补读缺失的统计部分。无关的群列表读取不会使个人分享缓存失效。

## 并发与失效

- 同一合并读取或两种分析维度的并发请求共用一个在途任务。
- 主动刷新启动新请求；迟到的旧请求不能覆盖新响应或回填过时的子缓存。
- 聚合结果携带本地请求顺序，避免较早发起的聚合覆盖后来取得的单项数据。未加入后的空榜单也会清掉旧榜单缓存。
- 注销、切账号、改头像昵称、排名可见性、群可见性等继续失效相关缓存；账号身份变化后的迟到结果不能恢复旧图片和资料。
- 公开分享读取继续实时校验撤销、有效期和参与者可见性；电脑同步状态检查、授权与预约写入保持各自流程。
- 海报和封面共用 5 分钟头像字节缓存及并发任务，每个 Canvas 自行解码；账号变化清空，失败不缓存，内存有上限，不写临时头像文件。
