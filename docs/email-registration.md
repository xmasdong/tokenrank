# 邮箱日报登记

2026-10-19 当前阶段只登记邮箱。尚未接入发信服务，不验证邮箱、不发送验证码或日报；不需要 Resend、SMTP 或 Cloudflare 邮件配置。`registered=true` 只代表已登记，`verified` 和 `delivery_enabled` 固定为 `false`，不能在界面声称已开启推送。

## 用户入口

- 「我的 → 消息提醒 → 完整邮箱日报」与日报详情的「完整邮箱日报 · 登记中」。
- 说明计划提供含缓存 Token 总量、调用次数、工具／模型占比、输入／输出和缓存明细。微信提醒仍为每次授权一条摘要；邮箱日报计划在后续版本支持持续每日接收。
- 用户自己填写邮箱，明确勾选“同意登记邮箱，用于 Token 用量日报”后，点击“登记邮箱”才写入。可在已登记状态修改或撤销。
- 不自动提取微信邮箱、不默认勾选、不在首次接入时新增强制弹窗、不把未验证的邮箱直接用于投递。
- 界面显示脱敏邮箱，修改时才带入本人填写的完整地址。登记页返回复用五分钟缓存，下拉刷新强制读新状态，保存与撤销只更新邮箱缓存，不清空用量、提醒或分享缓存。

## 接口和数据

`GET /api/email-registration`、`POST /api/email-registration`、`DELETE /api/email-registration` 均只允许本人有效的小程序会话。停用账号不能登记，电脑接入凭证不能访问。POST 必须传 `email`、`consent: true`、当前 `consent_version` 以及 GET 返回的 `expected_revision`（从未登记为 `null`）；DELETE 必须传当前 `expected_revision`。客户端不能指定目标用户或启用发送。

邮箱是私有资料，不进入 `/api/me`、公开榜单、分享、心跳或电脑端配置；仅登记接口向本人返回。邮箱与草稿不写入小程序持久存储。格式校验不是邮箱所有权验证，本地部分保留大小写，域名转为小写，不发送任何内容验证存在性。

新增 `email_registrations` 表保存账号、邮箱、同意版本与时间、随机版本号和创建／更新时间。撤销后清除邮箱及同意内容，只留下账号和随机版本等防并发元数据，避免迟到请求重新写回邮箱；注销事务删除整行。更新需要匹配版本，不覆盖其他设备更新；账号存在保护防止注销后的迟到写入。无新增发信调度、邮件密钥、发送任务或公开导出接口。

用户可以登记同一邮箱，但尚未证明地址归属。未来接入邮件投递时必须完成邮箱验证、明确开启每日接收、退订入口、同地址投递去重和故障状态处理，不能把当前登记直接批量启用；登记同意仅用于本项目 Token 日报，不扩大到营销。

## 部署与验证

1. 已有库只执行新增 `server/migrations/0014_email_registrations.sql`，再部署 Worker。新库直接使用 `server/schema.sql`。迁移仅创建邮箱表和账号保护，不更改任何用量、群榜或微信提醒。
2. 更新微信后台隐私指引，说明自愿填写的邮箱用于日报登记、不公开、可撤销，注销时删除；小程序表单、使用说明及注销说明已同步更新。
3. 运行项目测试，覆盖同意、账号隔离、非法输入、并发更新／撤销、注销、缓存、页面及旧功能。
4. 开发者工具用正式接口验证入口、未登记状态和缓存；真实邮箱写入只在用户主动提交时发生。测试合成邮箱只在内存 SQLite 和页面单元测试内使用，不写入生产库。
5. 后续发信服务选型与邮箱推送上线属于独立工作；当前版本不代表邮件送达验收，也不代表小程序正式版已发布。
