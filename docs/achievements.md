# 成就与数据页分享

## 入口与交互

「我的 → 我的成就」展示独立造型的奖章，三列排布，缩略图使用已达成的最高档（全未达成时使用第一档）；点击后进入独立成就卡页，使用原生返回回到收藏。卡片突出独立奖章、达成档位、日期、真实进度、作者和固定小程序码；下方可原位切换带缩略图的档位，七个多档系列的 28 档均有不同造型。底部固定「转发到群」「保存图片」，已达成档位才准备成就摘要和图片。原生转发在摘要就绪后即可使用，不等待 PNG；保存直接调用微信相册能力，仅在用户点保存时申请权限，拒绝后提供用户主动打开设置的入口，取消不提示成功。未达成／未开放档位客观展示状态，不导出或转发为已达成记录，可转发小程序入口。四项产出／价值造型折叠在「暂未开放」中，不伪造达成。

首页／我的收到已有同步记录的账号资料后检查新成就。隐私等原生提醒结束后，进入普通的原生成就卡片页，展示优先级最高的一枚及本次达成数量；使用系统返回退出，不再挂载自定义触摸遮罩。动效约 650 ms，图片加载后开始，无声音，可立即返回；支持关闭动效，并尊重系统减少动态效果。公开记录页不主动触发解锁展示。

首次展示分两阶段：准备接口只取得一分钟的临时占用，不写已展示收据；客户端等当前奖章图片加载、视图渲染、可见页面的动效结束后才确认整批展示。离页会释放未确认占用，崩溃或断网则自动过期，下次进入仍可补播。确认接口按账号与批次幂等，不能确认其他人的占用，准备后新增的成就不被顺带消费，数据修正后不再达成的主奖章不能确认。服务端依赖客户端渲染回报，不能判断用户是否注视屏幕；极端网络失败可能补播，优先避免漏播。

已有收据全部保留，不删除、不重置、不批量补写。用户可在「我的 → 我的成就 → 重播动效」播放已达成的最高优先级奖章，也可进入任意已达成卡片重播；只使用已读的真实成就，重播本身不调用准备／确认接口、不改变首次展示记录。未达成奖章不能播放为已达成。

## 真实规则

| 类别 | 条件 |
| --- | --- |
| 首次同步 | 当前设备已完成同步 |
| 累计调用 | 100、1,000、10,000、100,000 次 |
| 模型使用 | 1、3、5、10 种具名正用量模型 |
| 工具使用 | 2、3、5、8 种具名正用量工具 |
| 连续活跃 | 最长连续 3、7、30、100 个使用日 |
| 连续上传 | 最长连续 3、7、30、100 个实际上传日 |
| 历史单日最高 | 1、5、10、50 亿 Tokens |
| 累计用量 | 1、10、100、1,000 亿 Tokens |

口径为 `ranked_usage` 当前有效设备、含缓存总量和北京时间自然日，不能再加一遍缓存。无效／未来日期不计入；未知模型和未分类工具不算新增种类。最长历史连续记录不会因之后停止使用而消失。累计用量与单日记录可用真实历史重新核对，达成日取当前有效历史中首次满足条件的日期。

连续上传单独在服务端保存实际接收日期，不将历史使用日期当作上传日；只在完整报告或完整重建提交成功时登记，当天重试去重，不完整的暂存不计入。现有五分钟上报即可登记，无需为此升级电脑 CLI。此前没有该账本的上传日期不回填。

数据修正后重新计算资格；收据不能让不再满足条件的成就永久有效。禁用账号和注销遵循原有权限，注销删除两张成就表的关联记录。旧展示收据保留到注销，以免修正后又恢复相同门槛时重复自动弹出。

## API 与部署顺序

1. 新库使用 `server/schema.sql`；旧库依次执行 `server/migrations/0018_achievements.sql` 和 `0019_achievement_presentation.sql`。迁移仅新增表、索引和账号存在性触发器，保留用量和已有展示收据；注销账号同时删除其临时占用。
2. 部署包含新接口的 Worker。
3. 本地／真机验证后，再上传小程序。GitHub 同步、服务部署、小程序上传和审核分别执行。

- `GET /api/my/achievements`：本人会话，返回有效成就、未展示 ID 和数据 `snapshot`。
- `POST /api/my/achievements/prepare`：取得一分钟的展示占用，返回当批最高奖章、数量、本人目录及 `claim_id`；不消耗首次展示。并发设备只有一台取得有效占用。
- `POST /api/my/achievements/confirm`：携带 `claim_id`，在渲染和动效完成后确认当前准备批次；重复请求幂等。
- `POST /api/my/achievements/release`：携带 `claim_id`，离页释放当前占用，不修改已展示记录。旧凭据不能释放新的占用。
- `POST /api/my/achievements/claim`：保留旧版小程序兼容接口，仍是旧的即时确认语义；新版不再调用。
- `POST /api/shares`：`style=milestone`，携带 `badge_id`、`achievement_snapshot`。服务端重算资格、校验版本，仅保存展示所需摘要；数据变化返回 409。

成就分享沿用 `/pages/record/record?id=…`，访客免登录先看原作者的同款成就卡和分享时摘要，可直接继续转发、保存原作者卡片，底部保留「去看我的用量」「查看我的成就」。继续转发保留作者和原分享 ID，不静默登录或创建访客成就。收藏卡为象牙白纸面、深绿字色与原有薄珐琅奖章；封面和 PNG 使用同一色彩、真实档位／数字和固定码。公开读取会再次校验当前资格；修正后不再达成、禁用、注销、撤销或过期的记录不可继续读取。图片固定码只进入小程序，不承诺定位原作者。

普通成就读取与分享摘要复用五分钟缓存，并合并并发请求。准备会回填同响应中的真实目录，确认只失效成就缓存，不清空用量、群榜或分析缓存。页面离开、切换奖章和注销后的旧异步结果不覆盖当前视图。

## 档位资源

七个多档系列的 28 个门槛使用各自独立造型；包内资源由 `miniprogram/utils/milestone-art.js` 按原门槛选择，收藏、卡片、重播与图片导出共用，不新增网络图片请求，也不改动达成门槛。

## 真机重播与完成确认

重播通过组件的原生关键帧动画接口执行，每次播放使用独立编号并重置旧动画；只对奖章包装视图做透明度、缩放和位移动画，扫光使用独立视图，不依赖给原生图片重复增删 CSS 类。系统减少动态效果仍由样式覆盖，关闭动效时仅展示静态卡片。

点击后立即显示图片等待或播放状态。页面漏收图片的首次加载事件时，主动读取组件保存的就绪状态；无法确认时重建图片节点，迟到的旧图回调不能标记新图已加载。图片等待超过八秒、动画超过三秒未完成、接口不可用或执行失败，恢复按钮并提示重试。动画仅在当前账号、当前页面、当前奖章及当前播放编号的原生完成回调到达后确认；超时不会当作成功。静态展示仍等渲染后确认。重播导航失败也显示明确提示。

真机需重新打开含此修复的预览／开发／体验版本验证；模拟器、自动化测试及上传成功均不能替代真机验收。

## 奖章资源兼容

小程序包内所有奖章档位统一使用真实 PNG 文件，保留透明背景与原有尺寸、造型；不只更改扩展名。档位映射同时供收藏、原生成就卡、动效和 Canvas 分享图使用，旧分享按原门槛自动映射到新资源，不修改成就或历史收据。`project.config.json` 显式包含 `assets/badges`，避免动态路径引用的图片被包优化遗漏。

档位图片由已有资源解码为 RGBA，再以 pngquant 90–100 品质压缩成透明 PNG；逐张解码、校验尺寸和透明通道，并比较预览。回归测试检查 PNG 文件签名、全部档位路径和打包目录；预览构建仍需检查主包体积与真机图片加载。
