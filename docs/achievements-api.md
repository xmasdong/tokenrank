# 成就接口接入

成就接口先部署到服务端，小程序调用同一正式 API；不能只接前端后让线上持续返回 404。徽章图片、动效及页面设计可以单独继续验收。

部署顺序：

1. 执行 `server/migrations/0018_achievements.sql`，只新增实际上传日、首次展示收据两张表及其索引、账号存在性触发器。迁移幂等，不清空或改写已有用量。
2. 部署 Worker 的成就路由、上报登记、分享校验和注销清理逻辑。
3. 验证未登录请求返回 401，当前账号登录后 GET 返回 200，并确认原有用量和群榜仍可用，再上传小程序。

接口：

- `GET /api/my/achievements`：只读取当前会话账号的成就及待展示列表。忽略客户端传入的其他用户 ID。用量取当前有效设备，含缓存总量不再重复加缓存。
- `POST /api/my/achievements/claim`：按账号原子领取本批首次展示资格；同一成就跨手机不会重复自动弹出。只在小程序实际准备展示时调用，接口验收不提前领取用户的惊喜弹层。
- `POST /api/shares`，`style=milestone`：只允许分享服务端校验已达成、快照仍一致的成就；公开读取时重新校验资格，撤销、数据修正和注销后失效。

连续上传从迁移上线后实际接受的完整报告、完整重建提交开始登记，按北京时间每天去重；不把历史使用日期补造成历史上传日。原有五分钟同步协议可直接登记，不要求用户重装 CLI。

数据修正后按当前统计设备重新计算；禁用用户不能访问，注销会删除本人两张成就表记录，迟到的上报／领取不能重建已注销账号。未接入的产出和价值类指标继续标记未开放，不生成虚假达成。

GitHub 同步、Worker 部署、小程序上传、审核和正式发布分别记录。生产验收数据和凭证不进入公开仓库。
