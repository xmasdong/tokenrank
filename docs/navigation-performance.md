# 页面与周期切换性能

本次针对切页面／切周期后的等待，区分接口往返、服务端依赖链和额外绘图；不以访问量低推断延迟低，也不将桌面或模拟器耗时当作手机耗时。

## 已调整

- 个人概览和群列表的资料与统计并行读取；个人资料与同步健康并行读取。
- 群详情在通过身份、成员与资料检查后，并行读取资料、榜单和分析，保留原响应字段与权限判断。独立查询总数没有增加。
- 所有 API 响应附带 `Server-Timing: app;dur=…`，数值为 Worker 处理毫秒数，包含其等待数据库的时间。配合端到端请求时间区分网络／反代链路与服务端处理；不返回 SQL、身份或账号内容。
- 快捷分享仍预先准备原作者摘要，以保留一键转发。已导出的封面按当前账号版本和记录 ID 在页面内复用五分钟，上限八份，过期不复用，失效的异步回调不能恢复旧封面。返回页面或切回同一记录不重新导出 PNG。
- 群榜浏览与翻页不再自动生成完整海报；点击“预览图片”时生成，成功后直接预览，随后复用。分享封面仍保留，未生成时沿用原有默认封面。周期或数据改变会清除旧图，离页后不弹出迟到预览。
- 开启 `lazyCodeLoading: requiredComponents`，按当前页面所需加载自定义组件。统计缓存仍为五分钟；不增加周期预取，不改成固定数据或持久化私人统计。
- 榜单前八名头像直接加载，后续行使用微信原生图片延迟加载，减少一次加载整页 50 张头像造成的网络争用；头像服务原有的删除／失效规则不变。

## 验证与边界

使用同一份内存 SQLite 数据（20 群、6 名成员），为每次 D1 往返固定加入 25 ms 延迟，用于比较依赖链。以下是该次测试运行结果，不是生产或手机网络数据：

| 接口 | SQL 数量 | 调整前 | 调整后 |
| --- | ---: | ---: | ---: |
| 个人概览 | 7 | 180 ms | 132 ms |
| 群列表概览 | 6 | 131 ms | 79 ms |
| 群详情合并 | 9 | 161 ms | 83 ms |

并发回归测试阻塞资料查询，检查统计查询是否已经启动；完整请求合并测试仍核对权限、真实数值、分页、缓存与隐私字段。封面测试检查返回复用、周期隔离、账号变更和过期重绘；群榜测试检查浏览零长图导出、按需预览及离页保护。

2026-11-01 的本机公共接口基线：榜单三次请求约 1.37–1.64 秒，分析约 1.31–4.60 秒。该 Mac 链路存在本地代理，不能据此断言手机走相同路线或得出手机加速比例。现场记录保留在被忽略的 `artifacts/navigation-performance/`，不提交个人记录或凭证。真实手机仍需用新版预览确认切页、切周期和分享行为。
