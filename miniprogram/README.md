# 小程序流程与验收

## 页面职责

- 群榜：个人用量摘要、我的微信群列表、周期内的群排名、分享卡片发起排名。
- 广场：全站榜单与全站个人排名，始终可单独查看。
- 我的：个人用量面板、趋势、模型和工具明细，以及微信原生头像昵称、同步与接入管理。
- 分享卡片：用量账单、Token 卡片和白底排行榜三种模板；原账单与 Token 卡片保留宣纸／墨金选择，排行榜沿用微信运动式列表。每种生成微信转发封面与可保存的海报。
- 分享记录：免登录查看作者公开的本次摘要，底部固定“去看我的用量”按钮；再次转发仍展示原作者。
- 群详情：群名和单行同步状态之后直接展示周期与排名；底部固定自己的名次、头像、用量及“转发我的群内成绩”，点击自己的排名打开本人用量。榜名编辑为轻量入口，图片预览和完整榜单转发放在榜单后。
- 快捷接入：首屏选择 macOS／Windows 并复制专属安装命令；下方为同步状态、AI 协助提示词、原版项目说明和接入码管理。
- 使用说明：第一项是“连接电脑”和获取专属命令的按钮，之后才展示群榜规则、项目来源、同步与统计口径等解释。

## 电脑端新版本提示

心跳状态由服务端判断电脑端同步程序是否落后于当前发布版本（`sync_health.update_available`，版本号取自 `client/package.json`）。主要电脑落后时，进入群榜首页或群详情会自动弹窗，按电脑系统复制 macOS／Linux 或 Windows 更新命令；同一发布版本每天最多提示一次，主动关闭同步的电脑不提示。同步状态里同时显示一行新版本提示。以后发布新同步器只需部署服务端，不需要改小程序。

## 全站界面

2026-10-12 将首页、广场、群详情、我的用量、接入电脑、使用说明、分享卡片的外层页面、公开记录、账号管理及隐私组件统一为微信列表式界面。公共配色、系统字体、数字、等分标签和按钮统一由 `app.wxss` 提供；`styles/leaderboard.wxss` 只负责榜单排列，不另覆盖全局主题。首页移除印章与大报头，群列表为普通数字名次与细分隔线；我的用量与公开记录的主数字使用橙色，设置与资料表单使用普通列表分隔。绿色表示主要操作，蓝灰用于链接，红色专用于错误、注销和凭证重置。

原生顶部状态栏和导航栏同样使用白色、黑色文字，由 `app.json` 统一提供背景，所有页面继承该设置，群榜和广场不再单独覆盖为浅灰色。接入页仍先展示 macOS／Windows 与专属命令；头像昵称和隐私流程继续使用微信原生方案。分享图片的宣纸、墨金、小票和白底排行榜各自保留，页面主题不改变导出图片配色。账号注销与排名开关的实际行为保持原流程。

## 排行榜分享图片

2026-10-16 群页默认增加“我的群内成绩”：图片仅显示作者的头像昵称、来源群名、群内名次／同期上榜人数、本人 Token 用量与活跃记录。完整排行榜和 Token 榜单仍可选择；默认成绩卡与完整榜单邀请使用不同的原生转发入口，不把两种落地流程混用。

首页“我的用量”与个人页提供原生直接转发按钮，原分享编辑页改为次级“分享图片”入口。`utils/quick-share.js` 预先请求不可变公开记录，后台生成默认封面，不等待竖版海报、头像加载或相册授权。封面失败仍使用包内封面和正确作者链接；记录失败提供重试。周期切换、页面离开或注销后，迟到的记录与封面不能覆盖当前内容。`utils/achievement-poster.js` 同时绘制 1000×800 封面与 1000×1160 长图，保留完整固定小程序码。

`POST /api/shares` 可选 `group_id`，仅允许分享者使用本人已加入的群。服务端从同一用量口径计算 `usage.group_standing`，只公开群名、本人的名次、上榜人数与已加入人数，不公开群 ID、群身份、其他成员、凭证或个人历史。隐藏或零用量不虚构名次；数据在查询中发生变化时返回 409，客户端只自动重试一次。新字段保存在现有分享 JSON 中，无需数据库迁移；已有分享内容不变。先发布新版 Worker，再上传相应小程序。

开发者工具的产品验收直接打开本仓库 `miniprogram/`，`utils/api.js` 使用正式域名 `https://tokenrank.xmasdong.cn`；接口失败时保留错误状态，不替换成示例用量。独立成绩图预览运行 `node scripts/render-achievement.cjs <share-id> [output-dir]`（需安装 `@napi-rs/canvas`，可通过 `CANVAS_MODULE` 指定模块位置、`CARD_FONT` 指定中文字体）。脚本只从正式公开分享接口读取现有记录，缺少记录 ID 或接口失败即报错，不内置示例数字；默认输出到已忽略的 `artifacts/`，同时保留接口记录及来源时间，不能提交用户预览数据。

## 好友对比与工具偏好

群榜有“点头像，和 TA PK”提示。点击其他成员头像（含无头像的字头占位）先确认，再进入群内 PK；点击本人头像查看自己的用量。`POST /api/groups/:id/compare` 只接受周期、名次和榜单 snapshot，服务端校验登录、资料、同群成员及当前榜单，不能用昵称或客户端用户 ID 选人。榜单变化返回 `BOARD_CHANGED`，返回群榜强制刷新后重新选择。双方在同一读取事务中按北京时间、含缓存总量比较；无同期记录与真实零值分别处理。此入口只读、不代替群友创建公开分享；可保存带固定小程序码的对比图。个人分享卡原有的公开对比与转发流程保留。

公开分享页底部保留“去看我的用量”，新增“和 TA 比一下”。页面打开时只读取原作者的公开记录；用户主动点击后进入同期对比页，登录并请求 `POST /api/shares/:id/compare`。服务端忽略客户端提交的用量和身份，按原记录的北京时间起止日期读取参与者本人的数据，统一含缓存总量。累计卡片也按原作者展示的起止日期对比，旧卡片不拿当前周期凑数。没有同期上报返回 `NO_PERIOD_USAGE`，显示同步入口；真实上报过零用量可显示零。自比返回 `SELF_COMPARISON`，提供个人用量和工具偏好入口；旧统计口径不混用。

对比卡展示双方头像昵称、同期用量、活跃天数、调用次数和主要工具。封面和长图均携带固定小程序码，原生转发指向这张双人记录。公开接收页免登录，重转保留双方；点击“参与对比”继续对比原始作者，不套用参与者的个人数据或建立群关系。对比记录只保存原卡引用及参与者本人摘要，不复制原作者资料；原卡关闭、过期或原作者注销后，依赖它的对比也不可读。链接有效期不超过原卡，参与者可以单独关闭自己的对比链接。沿用现有 `usage_shares` 表，无需迁移或清空用户数据。

“我的 → 工具与模型 → 分享工具偏好”进入新模板；分享页也可直接切到“工具偏好”。`POST /api/shares` 的 `style=tools` 从真实同期明细生成前四个工具及剩余用量，缺失分类明确保留在“其他 / 未分类”中，不把最常用工具擅自补成 100%。普通用量卡仍只公开原有的主要工具，新模板额外公开所展示的工具用量和占比。白底、数字和占比条为主，不追加阵营称号或营销文案。

对比页的记录就绪后即可原生转发，图片慢或失败使用包内封面，链接仍指向正确双人记录。日期变化、页面离开或账号状态变化后，迟到的响应和图片不能覆盖当前内容。独立预览脚本支持成绩卡、工具偏好和双人对比，全部从正式分享接口取数。

## 工具／模型数据分析与广场偏好

“我的 → 工具与模型 → 数据分析”查看本人含缓存用量、工具／模型占比、每日趋势和明细。支持今日、近 7 天、近 30 天、累计；环形占比、趋势和明细切换复用同一份响应，不重新请求。今日与近 7 天趋势展示最近 7 天，近 30 天和累计趋势展示最近 30 天。未同步日期保留空值与断线，实际已上报零值显示零。点环形图或明细可聚焦单项，点折线可查看日期和数字。图形不可用时明细仍可阅读。

广场新增“总榜／工具／模型”。工具和模型视图展示真实 Token 分布、使用人数和常用人数，进入完整分析后可切换 Token 占比与常用人数占比，并点击“查看常用用户”。“用过”指本期有该项正用量；“常用”指本期按账号汇总后占比最高的一项，同量按名称顺序取一项。未分类份额最高（包括与主要项并列）时不推断偏好。人数占比采用互不重叠的常用人数，不能拿可重叠的使用人数画圆形比例。

分析和常用用户名单只读，沿用 `ranked_usage`／`public_usage` 的当前设备与隐私口径，不上传、清理或重新计算用户原始记录。`GET /api/my/analysis?period=...&dimension=tools|models` 要求本人会话；`GET /api/insights?...` 免登录提供公开聚合。公开分析链接先展示内容，不自动创建账号。隐藏排名、停用或未完成新版数据接入的账号不进入公开分析和名单；个人页始终可查看本人数据。若明细总量超出主总量，明确标记重叠并按明细总量计算占比，不修改源数据。

`GET /api/insights/users?period=...&dimension=...&name=...` 返回以所选项为主要工具或模型的公开用户，最多 50 人／页；后续请求携带 `offset` 与 `snapshot`。数值、偏好或隐私变化使快照改变，客户端重新读取首屏。只返回公开昵称、头像、所选项用量与占比，不返回原始用户 ID、设备信息或凭证。

激励广告预留在常用用户入口：客户端统一调用 `utils/insight-access.js` 的 `openInsight`，服务端统一经过 `server/src/insight-access.js`。当前默认 `free`，不创建广告实例，也不要求观看广告。后续通过 `setInsightAccessProvider` 接入播放流程，并在服务端实现独立的授权验证，才可启用激励模式。取消、未看完、缺少授权或页面离开后的结果均不能打开数据。不要把客户端回调、本地开关或 URL 参数当作授权。当前设置 `INSIGHTS_AUDIENCE_ACCESS=rewarded` 会拒绝名单请求，直至实现服务端验证；基本分析、个人用量与上传继续可用。广告位 ID、密钥及验证配置不得提交到公开仓库。

成绩卡打开 `/pages/record/record?id=...`，免登录先看原作者的成绩；重转仍保留原作者。页面不展示启动项目介绍弹窗，也不自动登录、加入群或跳转安装。用户主动点击“去看我的用量”后，已上传账号进入本人用量，无上报账号直接进入 macOS／Windows 设备选择页；下方另有“接入电脑”。从微信群进入时保留“查看本群排名”，由实际接收群的微信证明决定归属，正式参榜仍要求头像昵称。首页与群页取消自动首次接入弹窗，接入入口保持可见。

完整排行榜图片入口：我的 → 分享图片 → 排行榜，支持今日、近 7 天、近 30 天和累计；首页“分享图片”也进入同一页面。群详情榜单下方“分享图”可选择完整排行榜或原来的 Token 榜单，通过旁边“转发完整榜单”使用相应封面；底部主按钮始终分享本人成绩。

`utils/ranking-poster.js` 在小程序 Canvas 现场绘制：白底、名次、圆头像、单行昵称、右对齐橙色用量，达到一亿用两位小数的亿单位。海报展示前 5 名，转发封面展示前 3 名，人数超过截取范围时明确标出总上榜人数与展示范围。自己的名次独立保留，即使在已加载的 50 名之外；人数少时海报自动缩短。两种尺寸均携带包内固定小程序码。

个人排行榜从全站榜单取公开前几名，个人用量和名次必须与作者的公开记录一致；使用新榜单请求，一次不一致会自动重试，再不一致则停止出图并提示重新生成。新的图片类型复用现有个人摘要接口，不给公开记录增加其他人的历史或账号标识。点击个人卡片仍打开作者的公开展示页，访问者底部“去看我的用量”仍进入访问者自己的页面。群榜卡片仍以当前真实微信群识别为准，不用图片中的来源群建榜。

## 一个微信群一张榜

群榜与广场榜共用 `templates/leaderboard.wxml` 和 `styles/leaderboard.wxss`。2026-10-12 按实际参考截图调整为微信运动式白底榜单：普通数字名次、圆头像、单行昵称、橙色右对齐用量与细分隔线，前三名不加装饰。模型和调用次数在个人用量详情查看。本人行按服务端返回的本人名次标记“我”，不按昵称或头像识别；自己的名次超过首屏 50 人时仍固定可见。群内与全站名次在本人底栏同时显示，原生群分享入口保留。广场的原生 tabBar 已处理安全区，固定本人行不再重复增加底部留白。

布局参考：[微信运动截图所在文章](https://cloud.mo4tech.com/%E3%80%90redis-interview-question-%E3%80%91-how-to-use-redis-to-achieve-wechat-steps-leaderboard.html)、[跳一跳截图所在文章](https://www.epub360.com/blogs/article/5a5475be6c85696664cec141/)。仅借鉴排列方式，不复制品牌素材或添加无后端支持的点赞按钮。

群邀请入口统一为 `/pages/group/group?enter=1`；兼容旧 `create=1` 和携带 `g` 的卡片。先刷新微信登录态，再获取群加密数据，由服务端解密群身份并只读预览。已加入直接看榜；未加入显示确认页面，点击“加入本群排名”后重新获取微信证明，确认群身份与预览一致再建榜或加入。卡片来源群 ID 不参与决定入群归属。

`wx.getGroupEnterInfo` 的解密字段使用官方 `opengid`，兼容旧 `openGId` 和既有 `groupOpenId`，并拒绝互相冲突的群标识；`group_openid` 是用户在群中的身份，不能作为群唯一键，单聊标识也不建微信群榜。首页、群页、个人分享页和公开摘要转发均设置 `withShareTicket: true`，更新后应重新分享卡片，从手机微信群中的新卡片进入验证；扫描固定小程序码不能提供当前群身份。参考：[微信官方 API 定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。

官方群接口返回结构不要求 `watermark`：当前用户在本小程序的会话密钥成功解密后，允许不带水印的 `opengid`；如果存在水印，仍校验其 AppID，空水印或其他小程序水印不接受。旧字段没有水印时仍拒绝。不能因为缺水印直接提示“属于其他小程序”。仅发送卡片不建榜，发起人自己从群卡片打开并确认即可创建，不必等待别人；确认成功后出现在其“我的群榜”中。

群识别失败时显示原因，并提供重新识别、重新分享及回群列表入口。取消确认不会创建榜单或新增成员，不要求先安装客户端。初次确认建榜的用户可修改榜名，改名不影响微信群绑定。个人分享从群场景（1044 或微信 shareTicket）进入时增加本群入口，仍先展示作者摘要并保留“去看我的用量”；查看摘要不登录、不自动入群。

从已加入的群列表打开详情使用 `from=mine`，从接入页返回使用 `from=connect`；这两种内部导航沿用当前群 ID，并查询服务器确认用户已加入，不再次识别微信启动场景中的其他群。

服务端不允许仅凭群 ID 新增成员或直接创建未绑定的群，群榜数据仅对已加入成员开放。数据库 `uq_groups_wechat_identity` 对非空群身份哈希加唯一约束，并发确认也只能得到一张榜。升级先审计重复哈希，再执行 `0004_unique_wechat_group.sql`；若历史有重复，迁移会明确失败，不自动删除或合并。

群详情每次返回 50 位上榜成员，触底或点击“加载更多”继续，直到显示全部。顶部“X 人已加入”指确认加入这张群榜的人数；“本周期 Y 人上榜”统计所选周期总用量大于零的已加入成员，不以头像或昵称是否完整过滤。缺昵称使用默认名称，缺头像仍正常显示用量和名次。未上报、零用量不列入群排名，也不据此推断微信群总人数。自己的排名超过 50 名仍会在底部显示。

参与流程保留资料完善引导：点击“加入本群排名”后，如果头像或昵称缺失，在当前群页先完成微信原生资料表单；保存成功后重新获取群证明、校验原群身份，再完成加入。退出表单不创建群或成员关系。已加入但资料缺失的用户再次打开群页时仍会提示补全，但其已有用量继续列入群榜、分页人数与个人群名次，不因资料缺失隐藏；电脑同步及个人用量查看继续正常。

服务端 `/api/groups/resolve` 确认操作和群榜读取返回 428／`PROFILE_REQUIRED`，要求当前操作者先补全资料。`publicUser.profile_complete` 反映保存后的状态，首页对缺资料的本人显示“待完善资料”。榜单成员的已有用量不因资料缺失而被过滤，列表、总人数、分页快照与本人群名次沿用同一统计口径。完整资料用户直接继续。群页与个人页共用 `utils/profile-editor.js`、WXML 表单及样式，保留原生头像选择、昵称建议、微信隐私授权和失败重试，不自动替用户确认授权。

群榜接口首屏返回 `total`、`members`、`has_more`、`next_offset` 和 `snapshot`，续页携带 `offset` 与快照摘要。服务端仍校验当前成员身份，排名或群成员变化时返回 409，页面重新获取首屏，不拼接不同排名。续页请求不使用缓存；返回分享图预览后，有效首屏缓存下保留已展开的列表。加载失败保留旧列表并提供重试；切换周期、刷新或离开页面后丢弃迟到续页。

完整群榜微信封面展示前 3 名，长版海报展示前 5 名，均显示已加入人数、所选周期上榜人数和本人的群内排名。超出图片展示范围时明确标注“展示前 N 名”；图片不承载全部成员列表，完整排名在小程序内分页查看。完整榜单转发标题显示“X 人已加入”，固定小程序码和真实群识别入口不变；默认本人成绩卡按上节说明展示作者快照。

## 接入与返回

群详情始终区分群成员身份和电脑上报状态。群内连接电脑会传递来源群 ID。首次数据到达后优先返回原群页面；原页面栈已不存在时重新打开该群详情。

微信登录由页面自动完成，不把登录成功视为电脑已接入；是否收到过同步以 `last_report_at` 为准。首页、群详情和个人页的首次接入入口统一指向快捷接入页，加载或登录失败时首页仍提供入口。已有上报记录的用户仅显示同步状态，今日零用量、没有群榜或较久未同步不会重新显示首次接入说明。

快捷接入页在登录和命令请求期间也显示系统选择与操作步骤，失败就地重试，不展示占位安装命令。原版开源项目的完整说明和地址保留在命令区域之后。从帮助页获取命令时返回设备选择页顶部；没有来源群的接入完成入口打开本人用量，有来源群时仍返回原群。

接入页首次数据到达前每 5 秒检查一次，到达后每 30 秒检查一次，隐藏或卸载页面时停止检查。另提供手动检查和下拉刷新。同步器 0.2.10 起上报独立心跳；页面分别显示最近联系、检查和上传时间。超过 15 分钟无心跳显示“暂时联系不到电脑”，不区分休眠、断网与进程退出。明确收到停止事件才显示已关闭；旧版无心跳显示运行状态未知，不以用量上传时间推断存活。

切换系统会同步更新安装命令和 AI 提示词。安装脚本已经包含自启步骤，小程序不再要求重复安装自启。帮助页通过入口获取用户的真实接入命令，不再复制带占位符的命令。

安装介绍和帮助页共用原版项目说明，展示 Token Watcher 的采集、本地面板等功能、作者与 MIT 许可，以及可复制的[开源仓库](https://github.com/luwill/token-watcher)和[中文功能与使用说明](https://github.com/luwill/token-watcher/blob/main/README.zh-CN.md)。原版电脑面板默认地址为 `http://127.0.0.1:8787`，需在原版服务运行的电脑打开，自定义端口以本机配置为准。AI 接入提示词也包含原版来源，项目资料不依赖用户登录或接入命令加载。

## 个人用量与分享

首页、个人页、广场、群详情、日历、周报及工具／模型分析与趋势榜共用 5 分钟内存缓存，按当前登录会话、群、日期、周期和维度区分。有效缓存直接显示，不清空内容或闪加载占位；重复读取合并为一次请求。首次或缓存过期时重新获取，下拉刷新强制读取。日历及周报的默认日期会转为显式日期，避免再次打开同一范围时产生第二套请求。返回页面保留有效的选中日期、分析名单和已展开趋势列表。北京时间换日、重新登录、保存资料、确认入群、改榜名、调整排名可见性和重置接入码后清理缓存；接入页检测到新的同步时间也会清理。缓存不写持久化存储，最多保留 100 项；专属接入命令与可撤销的公开作者记录仍实时读取。

登录响应已包含用户资料，首次加载不再紧接着重复请求资料。页面独立的数据并行读取，迟到响应仍有页面／周期保护。分享摘要、周报分享及同期 PK 结果也在 5 分钟内按来源、数据版本、周期、样式和群复用，避免页面往返重复生成；刷新源用量、修改资料或撤销分享后不能复用旧摘要。记录提前过期时立即失效，失败结果不缓存。周报预览返回复用已生成图片；选排行榜样式先用缓存，确认榜单版本不一致才强制重取。该缓存不改变电脑每 5 分钟检查同步的频率；5 分钟是页面缓存的最长复用时间，用户可随时下拉读取最新数据。

`GET /api/my/usage?period=day|week|month|all` 根据小程序登录会话读取本人日汇总，与群成员身份和排名无关。首页摘要跟随首页周期；“我的”页提供今日、近 7 天、近 30 天和累计四种口径。今日趋势显示近 7 天；累计趋势显示近 30 天，累计总量仍包含全部已同步历史。

主用量直接采用原版 total_tokens（含缓存），输入、输出、缓存读取／写入单列。按北京时间 00:00 换日。工具和模型按相同总量口径合并，未分类差额单列，费用单独复用本机原版价格函数计算，仅作 API 等值估算。

首页群列表和用量分别处理加载与失败；请求失败不展示为零。周期切换、页面离开会丢弃迟到响应。个人分享使用服务端生成的公开摘要，原生转发链接进入 `pages/record/record?id=<随机分享ID>`，展示分享者的数据；图片使用固定小程序码，不绑定个人记录。摘要只含卡片上的昵称、头像地址、周期用量、同期全站名次、活跃记录和首位工具；不包含完整每日历史、模型明细、账号标识或接入凭证。

`activity` 根据全部已同步的非零 Token 或非零请求日期计算；同一天只记一次。今天尚未使用时连续记录保留至昨天，并明确截止日期；中断后展示历史最长连续。`standing` 按所选周期的正用量用户排名，同分按用户 ID，与榜单一致，不用虚构的百分位或名次鼓励分享。达到一亿统一用“2.58 亿”格式（保留两位小数），缩略值旁保留完整用量数字。

`POST /api/shares` 登录后只接受周期，数据由服务端读取；忽略客户端传入的数字与昵称。相同摘要复用 96 位随机入口，不同摘要独立保存，有效期 90 天；每人每天最多生成 50 份新摘要。`GET /api/shares/:id` 免登录读摘要。`POST /api/shares/:id/revoke` 仅本人可取消，失效后摘要不可访问，重新生成使用新入口；图片中的固定码不受记录撤销影响。该入口不加入任何群。历史记录的昵称与数字固定；头像仍引用上传时的地址，换头像使旧地址失效时显示昵称字头。

个人海报为 1000×1400，微信封面为 1000×800（5:4）。同一画布顺序导出，切换配色时取消旧结果，支持生成重试和相册权限设置。`utils/usage-poster.js` 是小程序和本地预览共用的绘制代码；根目录 `scripts/render-usage-cards.cjs` 使用 `@napi-rs/canvas` 在本地生成示例图片，全部为演示数据。

## 原生资料与独立同步器

“我的”页用 `button open-type="chooseAvatar"` 让用户选择头像，`input type="nickname"` 提供微信昵称建议，`form` 提交时读取最终原生值。不会静默抓取资料，不使用旧 getUserProfile 接口。取消选择不改资料，上传失败保留当前草稿；头像上传成功后保存服务端 URL，而不是临时文件路径。榜单使用保存后的头像和昵称。

页面通过 `wx.getPrivacySetting` 静默检查昵称授权。需要同意隐私指引时，先显示昵称启用入口，用户点击后调用 `wx.requirePrivacyAuthorize`，由微信展示官方隐私弹窗；同意后再聚焦原生昵称输入框。拒绝不影响用量查看，已同意不重复弹窗。头像整行（圆图、提示文字和箭头）均为同一个微信原生选择按钮。

微信后台「设置 → 服务内容声明 → 用户隐私保护指引」必须声明 **“收集你的昵称、头像”**，同时覆盖 `chooseAvatar` 与 `input type="nickname"`。用途为“用于展示用户个人资料、Token 用量分享卡片及用户主动参与的群排行榜”。仅配置 request / uploadFile 域名不能启用头像；缺少声明时微信报 `chooseAvatar:fail api scope is not declared in the privacy agreement`，在回调前直接拦截，表现为点击无反应。声明保存后按微信文档等待约 5 分钟生效，再重新打开小程序验收；代码不能绕过这项配置。依据：[隐私接口与信息类型对应表](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/miniprogram-intro.html)、[微信隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)。

项目默认启用合法域名校验。2026-09-28 用户补充微信后台配置后，重新打开项目并保持 `urlCheck: true`，真实登录用量、分享摘要、海报和作者展示页均验证成功，原 request 域名阻塞已解除。request 和 uploadFile 合法域名应包含 `https://tokenrank.xmasdong.cn`；头像上传、相册保存和真实微信转发仍须手机验收。不要以关闭校验作为发布验收。

头像通过 wx.uploadFile 提交到 `/api/profile`，携带已有小程序会话，401 重登后只重试一次。图片压缩目标 256×256，服务端限制 256 KiB、检查图片签名并持久化至 D1，每用户一份；微信后台需配置 uploadFile 合法域名。建议基础库 2.26.0+，支持头像昵称原生安全检查和压缩尺寸参数。实际交互还需真机检查。

连接电脑页和 AI 提示词对应 0.2.20 一键安装：缺失 token-watcher 时安装官方最新稳定版（最低 1.8.3）到用户目录并完成首次采集和后台启动；已有版本也检查最新稳定版，有更新时升级并重新计算，不会降级。低于 1.8.2 时暂停上传，1.8.2 的数据仍可正常上报。日常同步只读原版统计库，配置写 ~/.tokenrank，独立后台每 5 分钟检查，全部已保留历史分批回填。卸载同步器不会删除原版安装、数据或采集后台。

## 使用日历、个人周报与趋势榜

- **我的 → 使用日历**：按 GitHub 式热力小格查看截至所选月份的近 13 周，每列一周、每行一天；手机无需横向滚动。用量摘要与分享图使用同一区间。空心为未同步、浅灰为已同步零用量、四档绿色为真实用量；范围外和未来日期不填。点格子、选择日期或前后一天切换可查看当天用量、完整整数与预估费用，再进入日报／周报。新版接口复用已显示的每日明细；旧接口按需补齐并复用五分钟缓存。旧服务端未返回热力字段时使用完整七列的单月日历，按周一至周日横排并显示日期，不伪造三个月记录；页面和图片使用相同布局。旧接口没有设备、模型和费用明细时仅提示一次“暂无详细统计”，不将字段缺失归为用户未同步，不将缺失金额当作零费用；新版有真实零估算时仍显示金额。
- **我的 → 个人周报**：默认上一个完整周一至周日，可查看历史周与本周进度。显示活跃天数、调用次数、同步天数、单日峰值及最常用工具／模型。只有完整周且两周各有七天上报记录时才计算环比，零基期不计算百分比；零上报也是有效记录，缺记录不补零。
- **周报分享**：服务端验证所选周及内容摘要后生成固定分享记录，可选本人已加入的一个群展示该周名次（按当前成员重算）。转发无需等待图片生成；封面和长图都带官方固定小程序码。公开作者页免登录显示摘要，底部保留“去看我的用量”，重转仍是原作者。分享不包含私有日历、群 ID、接入凭证或完整历史。
- **广场 → 工具／模型趋势榜**：比较截至昨日的近 7／30 个完整自然日及其相邻上一期，支持每项去重使用人数和 Token 用量两种排序。每项使用人数可以重叠，不等于“常用”或用户主动表达喜好；仅统计当前公开且有效的选定设备样本。两期样本数分别显示，上期无记录不显示虚构增长，未分类不参与具名项排名。上期位次按当前数据重算，不是历史时点留档。转发路径固定结束日，续页每 50 项并校验快照，变化时重新读取首屏。

接口：`GET /api/my/calendar?month=YYYY-MM` 与 `GET /api/my/weekly?week=YYYY-MM-DD` 仅允许本人会话；`week` 必须是周一，省略时取上个完整周。`GET /api/insights/trends?period=week|month&dimension=tools|models&metric=users|tokens&end=YYYY-MM-DD` 允许匿名读取；续页携带 `offset` 和 `snapshot`。`POST /api/shares` 的 `style=weekly` 必须携带 `week` 与读取周报得到的 `week_snapshot`，可选 `group_id`；数据变化返回 `409/WEEK_CHANGED`。GET 只读已有日桶，不触发重算或清理；生成分享仅写入本人的摘要快照。继续复用现有 0011 表结构和 0.2.16 同步数据，无需数据库迁移或客户端升级。

## 订阅

底部第三个标签「订阅」记录用户为 AI 工具付的订阅费，交互照搬本地「超值」App 的订阅页。

- 用量归属：新版电脑端上传「工具 × 模型」明细（`tool_models_json`），按它判断谁计费：Cursor、Grok、Antigravity、Copilot、Windsurf 内运行的全部模型归该工具的订阅（如 Cursor 里的 Claude、Grok 归 X 订阅，Antigravity 里的 Claude 归 Google AI）；Claude Code、Codex 等代理按模型归属（其中接入的 GLM、Kimi、DeepSeek 由对应厂商计费，自定义模型归「综合」）；`grok-bot-*` 模型一律归 X 订阅。模型费用按各工具的 token 份额拆分。没有明细的旧数据按模型归属，并在订阅行注明「按模型估算」；无价格模型（Grok Bot、Cursor 自有的 composer、auto 等）的 token 单独统计并提示「回本偏低」。
- X 订阅：2026-10-12 起 xAI 的 The X Subscription 把 Grok、Grok Bot、Cursor、X Premium 合成一份订阅，共用每周额度（Plus $8、Premium $30、Super $100、Ultra $200，Grok Bot 需 Premium 及以上）。模板里 Cursor、Grok、Grok Bot 各有图标和入口，都归同一组；Cursor Pro／Pro+／旧 Ultra 和 SuperGrok 老套餐也归这一组。Grok Bot 暂用 Grok 图标。
- 用量推测：按近 7 天的归属推测正在用的服务，没有对应订阅的用量归为「综合」。已记录的服务不再推荐；点「记一笔」直接打开该服务的套餐表，「综合」按月估算填写。
- 列表页：右上角切换金额单位（人民币、美元、欧元、英镑、港币、日元），所有汇总、每天成本和 Token 价值按欧洲央行参考汇率（frankfurter.dev，缓存 6 小时；取不到时用标注日期的备用汇率）换算成同一单位，并注明汇率来源；每行仍显示原币价格。「今天 Token 值多少钱」与全部订阅的每天成本比较，标「已回本 N 倍」或「还差」；下面是近 7 天格子。订阅行带品牌图标、下次扣费日、每天成本，单一厂商的订阅另标该厂商模型今天的价值；同一厂商的多个订阅合并判断，标「N 个订阅合计」；「综合」对应其余模型的价值；Cursor、Copilot、Windsurf 不归属当天用量。
- 添加页：四列模板格子；多套餐弹出底部套餐表（含年付、包季），单套餐直接填入；币种可选六种；「保存并继续添加」连续录入多个订阅，「保存并返回」回到列表。套餐价格于 2026-10-21 核对：Claude、Cursor、GitHub Copilot、Google AI、Kimi 取官网，ChatGPT、Windsurf、智谱 GLM 官网无法直接读取，取多方二手资料，均可修改。
- 图标在 `assets/subscriptions/`：Claude、ChatGPT、Cursor、GitHub 取自「超值」项目，Gemini、Windsurf、Kimi、智谱 GLM 取自各官网 favicon，「综合」为自绘中性图标，统一 128×128 PNG。
- 换算：每天成本 = 每期价格 ÷ 周期天数（周 7、月 30、季 91、年 365、自定义 1–3650 天）；月均按 30.44 天、年均按 365 天。累计按开始日起已扣期数计算，续费当天计入新一期；暂停或取消后按停用日期截止。
- 回本按订阅的扣费周期判断：本期从开始日起已扣的最后一期算起，把这段时间该厂商模型的 API 等值估算（同厂商多个订阅按每天成本分摊）与这一期价格比较，显示「本期已回本 N 倍」或「本期还差 X」及剩余天数。顶部「今天 Token 值多少钱」和近 7 天格子只是当天价值与全部订阅每天成本的对照，不作为是否回本的结论。估算按北京时间自然日，用电脑端上传的 token-watcher 价格（`cost_json`），不代表实际账单。
- 订阅可标记「走 API Key 付费」：该订阅照常计成本，但不认领用量。Cursor、Copilot、Windsurf 这类多模型工具的订阅让全部用量（除按量充值和走 API Key 的厂商）计入总体对照，自身不单独判断回本。
- 按量充值（DeepSeek）：记录每次充值，也可填 DeepSeek 后台的当前余额「校准」。估算余额 = 最近一次校准余额（没有则为 0）+ 之后的充值 − 之后的估算花费；校准当天的花费视为已包含在填写的余额里。只计不带平台前缀、不带 `:cloud` 和 `-free` 的官方 deepseek 模型（如 dsh），经 WorkBuddy、OpenCode 等平台转发的用量由对方计费，归入「综合」。卡片显示估算余额、累计充值、估算已用、近 7 天日均和约可用天数；余额估算为负时提示校准。充值是实际花费，不计入订阅回本。记录保存在 `user_topups`（`0017`），每人最多 200 笔，注销时删除；接口 `POST /api/topups`、`POST/DELETE /api/topups/:id`，返回与订阅列表相同的完整数据。
- 分享订阅清单：列表页「分享我的 AI 订阅清单」在手机上用 Canvas 现场绘制「我每月的 AI 订阅清单」长图（`utils/subscription-poster.js`），不上传服务器，由用户自己转发或保存。每行为品牌图标、名称、套餐、本期回本倍数和每月价格（月付显示原价，年付、季付显示折合；同款合并为 ×N）；本期价值最高的一项标「主力」；按量充值按近 7 天日均折算「约 X/月」；顶部为近 30 天 API 等值与订阅回本倍数，底部为按显示单位换算的每月合计、所用汇率和小程序码。可选「隐藏金额」，价格与合计显示为 •••，只保留回本倍数。
- 订阅只在本人会话中读写，不进入排名、分享或公开分析；每人最多 30 条；注销账号时一并删除。金额以最小单位整数保存在 `user_subscriptions`（`0015`，`0016` 放开币种，`0017` 增加 `api_key`）。
- 接口：`GET/POST /api/subscriptions`，`POST/DELETE /api/subscriptions/:id`，返回完整列表、按币种与折合美元的汇总、近 7 天 `days`、`today_value`、`suggestions` 和所用汇率 `fx`；小程序缓存直接写回，不清空用量缓存。

## 用量日报与消息提醒

「我的 → 昨日用量日报」查看昨天的含缓存总量、调用次数、工具／模型与缓存明细。日历内可查看已结束日期的日报；微信消息携带固定日期，点开后展示该日期的数据。普通返回复用五分钟缓存，下拉刷新获取最新数据。

消息提醒的常规项为用量日报，预约下一个北京时间 09:00 发送前一天的摘要。原生授权每次对应一条提醒，发送后需要再次预约。旧周报预约不自动转成日报；个人周报及其分享功能继续保留。

「我的 → 消息提醒 → 完整邮箱日报」及日报详情可进入邮箱登记页：用户主动填写并勾选说明后保存，可修改或撤销。页面明确标注“尚未开放”，登记不等于开启推送；不会调用微信授权、发信或假装验证成功。邮箱仅在本人的登记接口返回，内存缓存五分钟，不存入设备持久化缓存，不公开到分享和榜单。后续接入发信时需先验证邮箱并主动开启接收。部署先执行 `0014_email_registrations.sql`，详见 [邮箱日报登记](../docs/email-registration.md)。

日报详情在用量总览下方显示下一次发送时间，点击「接收下一次日报」可直接完成一次原生授权及预约；不必跳到设置页。已预约显示预约日期，可进入管理提醒取消。通知链接的随机 `reminder_id` 用于核对刚消费的预约，只刷新提醒缓存；普通返回继续复用五分钟数据。授权后保存失败可重试同一个预约，不重复请求微信授权；拒绝不影响阅读。

## 日报快捷分享

日报总览下提供「转发日报」和「分享图片」，分享优先于续订提醒展示。卡片标题、封面和长图显示所选日期、含缓存 Token 总量、调用次数与主力工具／模型，长图还显示输入、输出及缓存读写；不把历史日报称为“今日”，不虚构名次或连续记录。封面与长图均携带固定小程序码。

`GET /api/my/daily` 增加 `snapshot`。`POST /api/shares` 使用 `style=daily`、明确的 `day` 及 `day_snapshot`；服务端重读本人的选中设备数据，版本不一致返回 `409/DAY_CHANGED`，页面只刷新重试一次。分享记录提前准备，不等待图片导出；重复返回复用分享缓存。缺记录不生成卡片，真实零用量可分享。此功能不需要数据库迁移。

分享链接和图片的小程序入口均指向 `/pages/record/record?id=...`，访客免登录查看原作者的固定摘要，重转仍保留作者，底部继续「去看我的用量」。仅公开选定一天的展示数字、主力工具及模型，不包含个人完整历史、邮箱、设备、接入凭证或提醒预约信息。原有链接撤销、到期与注销失效规则继续适用。

「分享图片」优先调用微信原生 [wx.showShareImageMenu](https://developers.weixin.qq.com/miniprogram/dev/api/share/wx.showShareImageMenu.html)，传本地图片 `path` 和公开记录的 `entrancePath`；旧微信或接口不可用时打开图片预览。取消不显示分享成功，不自动重开菜单。

热力图继续使用单次 `GET /api/my/calendar?month=YYYY-MM`：新增 `heatmap`（`from/to/end/daily/summary`），原单月 `daily/summary` 保持兼容。共用三条只读数据库语句；范围内读取日期、总量、调用次数、更新时间，以及自定义展示需要的模型和费用 JSON，不拉取工具明细。五分钟缓存不变，无新增数据库迁移；服务端和小程序需一起更新才能显示近 13 周。


日历页「显示内容」控制区间概览与分享图片，可独立勾选 Token 总量、使用设备、最常用模型和预计费用，默认只开启 Token，选择在本机保存。取消 Token 会隐藏概览总量、精确数值及分享图的峰值数值；四项全部关闭时，概览仍保留热力图与活跃／同步天数。私人日期详情独立展示当天含缓存用量、完整整数与预计费用（USD API 等值估算，非实际账单），不再展示调用次数。显示选项变化会清理图片缓存，阻止异步导出旧选项；私人日期详情不会自动加入未勾选费用的分享图。

`heatmap.details` 提供整个 13 周区间的最常用模型和费用，`heatmap.daily[].details` 提供该日期对应值。模型按已记录的具名模型 Token 排序；费用复用 `cost_json` 的 USD API 等值估算，注明非实际账单，缺少价格或上传时显示相应状态，不补成零。设备只展示 `usage_sync_state` 当前选定统计设备在 `sync_agents` 中上报的系统（macOS／Windows／Linux），不代表手机系统或历史设备型号，不返回设备 ID、主机名或路径；有详细统计但未记录设备时显示「暂无设备记录」，设备只在区间摘要展示一次。此选项不新增设备信息采集、数据库迁移或电脑端升级要求。旧日历接口缺少区间明细时，概览仅提示一次「暂无详细统计」，不猜测补齐。只有可用的真实费用金额使用橙色，缺失状态用普通文字。

点日期优先使用同一次日历响应中的每日费用，不新增请求。兼容旧服务端：仅在选定日期缺少明细且有真实同步记录时，复用该日 `GET /api/my/daily` 的五分钟缓存；当天复用今日用量缓存，不调用只允许已结束日期的日报接口。首次读取按需补齐，重复点选命中缓存，强制刷新可重新读取；数量与金额使用同一份日报，避免新旧数据混配。切换日期、月份、离页、跨账号时丢弃迟到结果；跨北京时间午夜后原今日使用已结束日报。费用缺失或缺价显示明确状态，失败仅影响金额区域并可单独重试，不显示假零。
