# 小程序流程与验收

## 页面职责

- 群榜：个人用量摘要、我的微信群列表、周期内的群排名、分享卡片发起排名。
- 广场：全站榜单与全站个人排名，始终可单独查看。
- 我的：个人用量面板、趋势、模型和工具明细，以及微信原生头像昵称、同步与接入管理。
- 分享卡片：纯数据模板，宣纸／墨金两种配色，微信转发封面与可保存的竖版海报。
- 分享记录：免登录查看作者公开的本次摘要，底部固定“去看我的用量”按钮；再次转发仍展示原作者。
- 群详情：群名和单行同步状态之后直接展示周期与排名；底部固定自己的排名、用量及“分享到微信群”。榜名编辑为创建者专属轻量入口，分享图预览和其他群榜入口放在榜单后。
- 快捷接入：首屏选择 macOS／Windows 并复制专属安装命令；下方为同步状态、AI 协助提示词、原版项目说明和接入码管理。
- 使用说明：第一项是“连接电脑”和获取专属命令的按钮，之后才展示群榜规则、项目来源、同步与统计口径等解释。

## 一个微信群一张榜

群邀请入口统一为 `/pages/group/group?enter=1`；兼容旧 `create=1` 和携带 `g` 的卡片。先刷新微信登录态，再获取群加密数据，由服务端解密群身份并只读预览。已加入直接看榜；未加入显示确认页面，点击“加入本群排名”后重新获取微信证明，确认群身份与预览一致再建榜或加入。卡片来源群 ID 不参与决定入群归属。

`wx.getGroupEnterInfo` 的解密字段使用官方 `opengid`，兼容旧 `openGId` 和既有 `groupOpenId`，并拒绝互相冲突的群标识；`group_openid` 是用户在群中的身份，不能作为群唯一键，单聊标识也不建微信群榜。首页、群页、个人分享页和公开摘要转发均设置 `withShareTicket: true`，更新后应重新分享卡片，从手机微信群中的新卡片进入验证；扫描固定小程序码不能提供当前群身份。参考：[微信官方 API 定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。

官方群接口返回结构不要求 `watermark`：当前用户在本小程序的会话密钥成功解密后，允许不带水印的 `opengid`；如果存在水印，仍校验其 AppID，空水印或其他小程序水印不接受。旧字段没有水印时仍拒绝。不能因为缺水印直接提示“属于其他小程序”。仅发送卡片不建榜，发起人自己从群卡片打开并确认即可创建，不必等待别人；确认成功后出现在其“我的群榜”中。

群识别失败时显示原因，并提供重新识别、重新分享及回群列表入口。取消确认不会创建榜单或新增成员，不要求先安装客户端。初次确认建榜的用户可修改榜名，改名不影响微信群绑定。个人分享从群场景（1044 或微信 shareTicket）进入时增加本群入口，仍先展示作者摘要并保留“去看我的用量”；查看摘要不登录、不自动入群。

从已加入的群列表打开详情使用 `from=mine`，从接入页返回使用 `from=connect`；这两种内部导航沿用当前群 ID，并查询服务器确认用户已加入，不再次识别微信启动场景中的其他群。

服务端不允许仅凭群 ID 新增成员或直接创建未绑定的群，群榜数据仅对已加入成员开放。数据库 `uq_groups_wechat_identity` 对非空群身份哈希加唯一约束，并发确认也只能得到一张榜。升级先审计重复哈希，再执行 `0004_unique_wechat_group.sql`；若历史有重复，迁移会明确失败，不自动删除或合并。

群详情每次返回 50 位上榜成员，触底或点击“加载更多”继续，直到显示全部。顶部“X 人已加入”指确认加入这张群榜的人数；“本周期 Y 人上榜”统计所选周期总用量大于零的已加入成员，不以头像或昵称是否完整过滤。缺昵称使用默认名称，缺头像仍正常显示用量和名次。未上报、零用量不列入群排名，也不据此推断微信群总人数。自己的排名超过 50 名仍会在底部显示。

参与流程保留资料完善引导：点击“加入本群排名”后，如果头像或昵称缺失，在当前群页先完成微信原生资料表单；保存成功后重新获取群证明、校验原群身份，再完成加入。退出表单不创建群或成员关系。已加入但资料缺失的用户再次打开群页时仍会提示补全，但其已有用量继续列入群榜、分页人数与个人群名次，不因资料缺失隐藏；电脑同步及个人用量查看继续正常。

服务端 `/api/groups/resolve` 确认操作和群榜读取返回 428／`PROFILE_REQUIRED` 拦截缺资料账号，不能仅绕过界面参榜。`publicUser.profile_complete` 反映保存后的状态。群榜列表、总人数、分页快照与本人群名次统一排除资料不完整者；首页相应显示“待完善资料”。完整资料用户直接继续。群页与个人页共用 `utils/profile-editor.js`、WXML 表单及样式，保留原生头像选择、昵称建议、微信隐私授权和失败重试，不自动替用户确认授权。

群榜接口首屏返回 `total`、`members`、`has_more`、`next_offset` 和 `snapshot`，续页携带 `offset` 与快照摘要。服务端仍校验当前成员身份，排名或群成员变化时返回 409，页面重新获取首屏，不拼接不同排名。续页请求不使用缓存；返回分享图预览后，有效首屏缓存下保留已展开的列表。加载失败保留旧列表并提供重试；切换周期、刷新或离开页面后丢弃迟到续页。

群榜微信封面展示前 3 名，长版海报展示前 5 名，均显示已加入人数、所选周期上榜人数和本人的群内排名。超出图片展示范围时明确标注“展示前 N 名”；图片不承载全部成员列表，完整排名在小程序内分页查看。转发标题也显示“X 人已加入”，固定小程序码和真实群识别入口不变。

## 接入与返回

群详情始终区分群成员身份和电脑上报状态。群内连接电脑会传递来源群 ID。首次数据到达后优先返回原群页面；原页面栈已不存在时重新打开该群详情。

微信登录由页面自动完成，不把登录成功视为电脑已接入；是否收到过同步以 `last_report_at` 为准。首页、群详情和个人页的首次接入入口统一指向快捷接入页，加载或登录失败时首页仍提供入口。已有上报记录的用户仅显示同步状态，今日零用量、没有群榜或较久未同步不会重新显示首次接入说明。

快捷接入页在登录和命令请求期间也显示系统选择与操作步骤，失败就地重试，不展示占位安装命令。原版开源项目的完整说明和地址保留在命令区域之后。从帮助页获取命令时返回设备选择页顶部；没有来源群的接入完成入口打开本人用量，有来源群时仍返回原群。

接入页首次数据到达前每 5 秒检查一次，到达后每 30 秒检查一次，隐藏或卸载页面时停止检查。另提供手动检查和下拉刷新。超过 3 小时没有上报时显示“较久未同步”，不据此断言客户端故障。

切换系统会同步更新安装命令和 AI 提示词。安装脚本已经包含自启步骤，小程序不再要求重复安装自启。帮助页通过入口获取用户的真实接入命令，不再复制带占位符的命令。

安装介绍和帮助页共用原版项目说明，展示 Token Watcher 的采集、本地面板等功能、作者与 MIT 许可，以及可复制的[开源仓库](https://github.com/luwill/token-watcher)和[中文功能与使用说明](https://github.com/luwill/token-watcher/blob/main/README.zh-CN.md)。原版电脑面板默认地址为 `http://127.0.0.1:8787`，需在原版服务运行的电脑打开，自定义端口以本机配置为准。AI 接入提示词也包含原版来源，项目资料不依赖用户登录或接入命令加载。

## 个人用量与分享

首页、个人页、广场和群详情共用 60 秒内存缓存，按当前登录会话、群和周期区分。有效缓存直接显示，重复读取合并为一次请求；首次或缓存过期时重新获取，下拉刷新始终请求最新数据。北京时间换日、重新登录、保存资料、确认入群、改榜名和重置接入码后清理缓存；接入页检测到新的同步时间也会清理。缓存不写本地持久化存储，不缓存专属接入命令或可撤销的公开分享记录。

登录响应已包含用户资料，首次加载不再紧接着重复请求资料。页面独立的数据并行读取，迟到响应仍有页面／周期保护。该缓存不改变电脑每 5 分钟检查同步的频率；60 秒指页面数据复用时间，不是采集周期。

`GET /api/my/usage?period=day|week|month|all` 根据小程序登录会话读取本人日汇总，与群成员身份和排名无关。首页摘要跟随首页周期；“我的”页提供今日、近 7 天、近 30 天和累计四种口径。今日趋势显示近 7 天；累计趋势显示近 30 天，累计总量仍包含全部已同步历史。

主用量直接采用原版 total_tokens（含缓存），输入、输出、缓存读取／写入单列。按北京时间 00:00 换日。工具和模型按相同总量口径合并，未分类差额单列，不估算费用。

首页群列表和用量分别处理加载与失败；请求失败不展示为零。周期切换、页面离开会丢弃迟到响应。个人分享使用服务端生成的公开摘要，原生转发链接进入 `pages/record/record?id=<随机分享ID>`，展示分享者的数据；图片使用固定小程序码，不绑定个人记录。摘要只含卡片上的昵称、头像地址、周期用量、同期全站名次、活跃记录和首位工具；不包含完整每日历史、模型明细、账号标识或接入凭证。

`activity` 根据全部已同步的非零 Token 或非零请求日期计算；同一天只记一次。今天尚未使用时连续记录保留至昨天，并明确截止日期；中断后展示历史最长连续。`standing` 按所选周期的正用量用户排名，同分按用户 ID，与榜单一致，不用虚构的百分位或名次鼓励分享。达到一亿统一用“2.58 亿”格式（保留两位小数），缩略值旁保留完整用量数字。

`POST /api/shares` 登录后只接受周期，数据由服务端读取；忽略客户端传入的数字与昵称。相同摘要复用 96 位随机入口，不同摘要独立保存，有效期 90 天；每人每天最多生成 50 份新摘要。`GET /api/shares/:id` 免登录读摘要。`POST /api/shares/:id/revoke` 仅本人可取消，失效后摘要不可访问，重新生成使用新入口；图片中的固定码不受记录撤销影响。该入口不加入任何群。历史记录的昵称与数字固定；头像仍引用上传时的地址，换头像使旧地址失效时显示昵称字头。

个人海报为 1000×1400，微信封面为 1000×800（5:4）。同一画布顺序导出，切换配色时取消旧结果，支持生成重试和相册权限设置。`utils/usage-poster.js` 是小程序和本地预览共用的绘制代码；根目录 `scripts/render-usage-cards.cjs` 使用 `@napi-rs/canvas` 在本地生成示例图片，全部为演示数据。

### 固定小程序码与个人展示页

个人海报、转发封面和群榜分享图统一嵌入 `assets/mini-program-code.jpg`，即用户于 2026-09-28 提供的 258×258 原图。文件原样纳入小程序包，只在画布中等比放置于圆形白底，保留 6% 内边距；圆形蒙版仅裁掉白色四角，完整保留码点与右下角微信标识；加载不调用微信生成码接口、不要求额外网络请求或文件写入。图片旁标注“扫码进入小程序”，具体扫码目标沿用原码。码图解码失败时显示重试，不导出缺码图片。

微信原生个人卡片的 path 携带随机分享 ID，点击后打开作者公开展示页；页面仅请求该公开摘要，不查询访问者的私人用量。底部固定“去看我的用量”按钮，点击后 switchTab 到 `pages/profile/profile`，再按访问者自己的登录态展示用量。展示页再次转发保留原作者和记录 ID，不变为群邀请。

群邀请仍从群榜等入口进入 `/pages/group/group?enter=1`，识别卡片所在真实微信群。固定小程序码不会自动加入来源群。

旧 `scene=s=<ID>&m=a|s|t` 入口及服务端动态码接口保留兼容；新版分享图片不再调用它们。`scripts/render-usage-cards.cjs` 默认加载与小程序同一份固定码资源，预览中的统计数据仍为演示数据。未执行微信真机扫码验收；发布前需检查固定码长按识别、个人卡片落地、再次转发及底部按钮。

已知数据限制：累计仅指服务端已同步的历史；现有上报协议按用户和日期取最大累计值，尚不能准确累加多台独立电脑，也不能据此宣称覆盖未上传的本机历史。

## 原生资料与独立同步器

“我的”页用 `button open-type="chooseAvatar"` 让用户选择头像，`input type="nickname"` 提供微信昵称建议，`form` 提交时读取最终原生值。不会静默抓取资料，不使用旧 getUserProfile 接口。取消选择不改资料，上传失败保留当前草稿；头像上传成功后保存服务端 URL，而不是临时文件路径。榜单使用保存后的头像和昵称。

页面通过 `wx.getPrivacySetting` 静默检查昵称授权。需要同意隐私指引时，先显示昵称启用入口，用户点击后调用 `wx.requirePrivacyAuthorize`，由微信展示官方隐私弹窗；同意后再聚焦原生昵称输入框。拒绝不影响用量查看，已同意不重复弹窗。头像整行（圆图、提示文字和箭头）均为同一个微信原生选择按钮。

微信后台「设置 → 服务内容声明 → 用户隐私保护指引」必须声明 **“收集你的昵称、头像”**，同时覆盖 `chooseAvatar` 与 `input type="nickname"`。用途为“用于展示用户个人资料、Token 用量分享卡片及用户主动参与的群排行榜”。仅配置 request / uploadFile 域名不能启用头像；缺少声明时微信报 `chooseAvatar:fail api scope is not declared in the privacy agreement`，在回调前直接拦截，表现为点击无反应。声明保存后按微信文档等待约 5 分钟生效，再重新打开小程序验收；代码不能绕过这项配置。依据：[隐私接口与信息类型对应表](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/miniprogram-intro.html)、[微信隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)。

项目默认启用合法域名校验。2026-09-28 用户补充微信后台配置后，重新打开项目并保持 `urlCheck: true`，真实登录用量、分享摘要、海报和作者展示页均验证成功，原 request 域名阻塞已解除。request 和 uploadFile 合法域名应包含 `https://tokenrank.xmasdong.cn`；头像上传、相册保存和真实微信转发仍须手机验收。不要以关闭校验作为发布验收。

头像通过 wx.uploadFile 提交到 `/api/profile`，携带已有小程序会话，401 重登后只重试一次。图片压缩目标 256×256，服务端限制 256 KiB、检查图片签名并持久化至 D1，每用户一份；微信后台需配置 uploadFile 合法域名。建议基础库 2.26.0+，支持头像昵称原生安全检查和压缩尺寸参数。实际交互还需真机检查。
